# ADS124S18 Precision ADC Driver for MSPM0G3507

A complete embedded driver and example code for the **Texas Instruments ADS124S18** 24-bit precision analog-to-digital converter (ADC), designed for the MSPM0G3507 LaunchPad.

## Overview

The ADS124S18 is a delta-sigma ADC with integrated sequencer for multi-channel measurement applications. This project provides:
- **Complete driver layer** for SPI communication and register management
- **Hardware abstraction layer** for easy porting to other MSPM0 variants
- **Two example applications** (continuous conversion and sequencer-based scanning)
- **Data integrity features** (SPI CRC, register map protection, status monitoring)
- **Power management** (active and standby modes with configurable timing)

**Key Features:**
- 24-bit ADC resolution with support for 16-bit variants
- Up to 18 input channels (supports 8-channel variants)
- 24 programmable sequencer steps for automated multi-channel scanning
- Integrated offset and gain calibration
- SPI communication with optional CRC validation

**Documentation:**
- [ADS124S18 Datasheet](https://www.ti.com/product/ADS124S18)
- [PADC Design Calculator](https://dev.ti.com/gallery/view/PADC/PADC_Design_Calculator_Tool/?device=ADS124S18) - For configuration code generation

## Quick Start

### Build and Run
1. Open the project in Code Composer Studio or TI's online IDE
2. Configure the SPI and GPIO pins (via M0-Launchpad.syscfg)
3. Compile and load to MSPM0G3507 LaunchPad
4. The main_nortos.c file automatically runs simpleADC() on startup

### Select Operating Mode
Edit main_nortos.c to choose between two example modes:

```C
// Option 1: Simple continuous single-channel conversion
simpleADC();

// Option 2: Multi-channel sequencer scanning (4 channels)
sequencerExample();
```

## Architecture Overview

### Register Map Organization
The ADS124S18 uses a 25-page memory organization:

| Page | Name | Registers | Purpose |
|------|------|-----------|---------|
| 0 | GENERAL_SETTINGS | 64 | Global ADC configuration, status, control |
| 1-24 | STEP_0 to STEP_23 | 24 each | Sequencer step configurations (one per channel) |

Each sequencer step can independently configure:
- Input channels (positive and negative)
- Programmable gain amplifier (PGA)
- Digital filter type and over-sampling ratio (OSR)
- Offset and gain calibration
- Conversion delay
- IDAC excitation current (optional)

### Shadow Register Architecture
The driver maintains a software copy (`registerMap[][]`) of all registers to:
- Minimize SPI transactions for page switching
- Enable efficient local register lookups
- Support automatic page management
- Track register state for debugging

### Data Flow

```
┌─────────────────────────────────────────────────────────────┐
│ ADC Measurement Cycle                                       │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. startAdcConversion()        → ADC begins conversion    │
│  2. waitForDRDYinterrupt()      → Wait for data ready      │
│  3. readData()                  → Fetch 24-bit result      │
│  4. checkStatus() [optional]    → Verify no errors         │
│                                                             │
│  [Repeat steps 1-4 for each sample]                        │
│                                                             │
│  5. stopAdcConversion()         → Stop conversions         │
│  6. powerDownMode()             → Enter low-power mode     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Peripherals & Pin Assignments

Visit [LP_MSPM0G3507](https://www.ti.com/tool/LP-MSPM0G3507) for LaunchPad information, hardware files, and user guide.

| Peripheral | Pin | Function | Details |
|------------|-----|----------|---------|
| SPI0 | PB9 | SCLK (Clock) | Mode: 0/0 (CPOL=0, CPHA=0), Speed: 1-10 MHz |
| SPI0 | PB8 | PICO (Peripheral In, Controller Out) | Active high |
| SPI0 | PB7 | POCI (Peripheral Out, Controller In) | Active high |
| SPI0 | PB0 | CS (Chip Select) | Active low (manual or hardware controlled) |
| GPIO | PA13 | DRDYn (Data Ready) | Falling edge interrupt, active low |

### Pin Configuration Notes

**MSPM0 SPI Interface:**
- Configure in SysConfig (M0-Launchpad.syscfg) under SPI
- Supports up to 10 MHz with proper signal integrity
- Uses 8-bit frame format with 16-bit FIFO packing in firmware

**DRDY Signal:**
- Falling edge indicates conversion data is ready
- Configured as GPIO interrupt (GROUP1)
- ISR sets `flag_nDRDY_INTERRUPT` flag for edge detection


## Operating Modes

### Mode 1: Simple Continuous Conversion (Single Channel)

**Use Case:** Continuous measurement of one differential signal (e.g., thermocouple, load cell)

**Features:**
- Offset calibration performed on initialization
- Continuous conversion without sequencer
- Low software overhead
- Typical throughput: 100-250 SPS (configurable via OSR)

**Entry Point:**
```C
simpleADC();  // Runs indefinitely, set g_collectData=false to stop
```

**Key Settings:**
- Reference: 2.5V internal (configurable to external)
- Clock mode: 256 kHz (configurable)
- Filter: SINC4 with OSR 512 (8192 for calibration)
- Inputs: AIN0 (positive) vs AIN1 (negative)
- Output data rate: ~250 SPS

### Mode 2: Multi-Channel Sequencer Scanning

**Use Case:** Automated measurement of multiple channels in fixed sequence (e.g., monitoring 4 temperature sensors)

**Features:**
- 4 pre-configured sequencer steps (one per channel)
- Hardware-managed channel switching
- Lower software overhead than manual switching
- Deterministic channel timing

**Entry Point:**
```C
sequencerExample();  // Runs indefinitely, set g_collectData=false to stop
```

**Sequence Configuration:**
- Step 0: Channel AIN0
- Step 1: Channel AIN1
- Step 2: Channel AIN2
- Step 3: Channel AIN3
- 8 conversions per step = 32 total samples per cycle
- 200 ms pause between cycles

**Customizing Steps:**
Edit `ADS124S18_RegisterDetails.h` to configure step parameters (generated by PADC Calculator).

## Data Integrity Features

The driver supports three levels of error detection:

### 1. SPI CRC Validation (SPI_CRC_ENABLED)
- Validates each SPI transaction payload
- Detects single-bit errors in command/data
- Optional per-transaction via `isValidCrcOut()`

**Enable in RegisterDetails:**
```C
{.addr = 0x16, .value = 0x05}  // MONITOR_CFG with SPI_CRC_EN set
```

### 2. Status Register Monitoring (STATUS_ENABLED)
- Every SPI transaction includes STATUS_MSB and STATUS_LSB
- Detects ADC errors (reset, supply issues, conversion errors)
- Call `checkStatus()` before/after critical operations

**Error Flags:**
- STATUS_MSB[1]: Reset detected
- STATUS_MSB[2]: Supply/ADC status error
- STATUS_LSB[0]: SPI CRC error
- STATUS_LSB[1]: Register access error

### 3. Register Map CRC Protection (REGMAP_CRC)
- Validates all internal register memory against corruption
- Computed and stored on-demand via `enableRegisterMapCrc()`
- Detects bit flips from noise or EMI
- Adds overhead to register access

**Usage:**
```C
enableRegisterMapCrc(true);   // Compute and enable protection
STATUS_IO status = checkStatus();
// Monitor status.SUPPLY_STATUS and status.ADC_STATUS for CRC errors
```

## API Reference

### Initialization Functions
```C
bool resetDevice(void);
```
- Performs hardware reset via SPI command
- Restores all registers to power-on defaults
- Required before first use
- **Duration:** ~500 µs

```C
void initADC(void);
```
- Loads register configuration from ADS124S18_RegisterDetails.h
- Initializes all sequencer steps
- Clears status flags
- **Duration:** ~50-100 ms (depends on number of steps)

### Control Functions
```C
void startAdcConversion(void);
```
- Begin continuous or sequencer-based conversions
- ADC transitions from idle to active

```C
void stopAdcConversion(void);
```
- Stop ongoing conversions gracefully
- Current conversion completes, then ADC idles

```C
void powerDownMode(void);
```
- Enter low-power standby
- ADC stops conversions
- Typical power: <1 mW (standby) vs 5-10 mW (active)

```C
void activeMode(void);
```
- Exit standby and prepare for conversions
- ADC ready for measurement after this call

### Data Acquisition Functions
```C
ADC_IO readData(void);
```
- Wait for DRDY signal and retrieve latest conversion
- Returns 24-bit (or 16-bit) ADC result
- Optional STATUS and CRC included
- **Typical latency:** 100-500 µs (depends on OSR setting)

```C
STATUS_IO checkStatus(void);
```
- Read all ADC status registers
- Returns summary and detailed error flags
- **Use case:** Diagnose communication or hardware issues

### Register Access Functions
```C
REG_IO readSingleRegister(uint8_t page, uint8_t address);
REG_IO writeSingleRegister(uint8_t page, uint8_t address, uint8_t data);
```
- Low-level register read/write via SPI
- Automatically manages page switching
- Updates shadow register cache
- **Duration:** ~50 µs per transaction

```C
uint8_t getRegisterValue(uint8_t page, uint8_t address);
```
- Fast local read from shadow register cache
- No SPI communication
- **Duration:** ~1 µs

### Utility Functions
```C
int32_t signExtend(const uint8_t dataBytes[]);
```
- Convert 3-byte ADC reading to signed 32-bit integer
- Handles two's complement correctly for differential measurements

```C
void enableRegisterMapCrc(bool enable);
bool isValidCrcOut(void);
```
- Manage register map CRC protection
- Validate last SPI transaction CRC

### Timing Functions
```C
void delay_us(uint32_t delay_time_us);
void delay_ms(uint32_t delay_time_ms);
bool waitForDRDYinterrupt(uint32_t timeout_ms);
```
- Microsecond/millisecond delays using cycle counting (31 MHz reference)
- Interrupt-driven DRDY waiting (efficient vs. polling)

The easiest way to generate ADC configurations is using the **PADC Design Calculator** tool:

2. Select Device: ADS124S18
3. Configure:

5. Replace the existing RegisterDetails.h in the Driver folder

### Generated Configuration Structure

The tool generates a `ADS124S18_sequencer_config[]` array that the driver automatically loads via `initADC()`. 

**Example configuration:**
```C
// Generated by PADC Design Calculator Tool
#define ARRAY_SIZE(arr) (sizeof(arr) / sizeof((arr)[0]))

typedef struct {
    const uint8_t addr;
    const uint8_t value;
} RegisterConfig;

typedef struct {
    const uint8_t pageNumber;
    const RegisterConfig *configPointer;
    const int registerCount;
} PageConfig;

// Global (Page 0) Configuration - ADC and sequencer settings
RegisterConfig global_page_config[] = {
    {.addr = 0x10, .value = 0x46},  // ADC_CFG: Internal 2.5V ref, 256kHz clock
    {.addr = 0x11, .value = 0x04},  // DIGITAL_CFG: 24-bit, status output enabled
    {.addr = 0x16, .value = 0x05},  // MONITOR_CFG: SPI CRC enabled
    {.addr = 0x19, .value = 0x90},  // SEQUENCER_CFG: Sequencer enabled
    {.addr = 0x1A, .value = 0x0F},  // SEQUENCE_STEP_EN_0: Enable steps 0-3
};

// Sequencer Step Configurations (Pages 1-4 for 4-channel example)
RegisterConfig step0_config[] = {
    {.addr = 0x00, .value = 0x00},  // AINP: Select AIN0
    {.addr = 0x01, .value = 0x08},  // AINN: Select AINCOM
    {.addr = 0x03, .value = 0x07},  // DIGITAL_CFG: 24-bit format
};

RegisterConfig step1_config[] = {
    {.addr = 0x00, .value = 0x01},  // AINP: Select AIN1
    {.addr = 0x01, .value = 0x08},  // AINN: Select AINCOM
    {.addr = 0x03, .value = 0x07},  // DIGITAL_CFG: 24-bit format
};

RegisterConfig step2_config[] = {
    {.addr = 0x00, .value = 0x02},  // AINP: Select AIN2
    {.addr = 0x01, .value = 0x08},  // AINN: Select AINCOM
    {.addr = 0x03, .value = 0x07},  // DIGITAL_CFG: 24-bit format
};

RegisterConfig step3_config[] = {
    {.addr = 0x00, .value = 0x03},  // AINP: Select AIN3
    {.addr = 0x01, .value = 0x08},  // AINN: Select AINCOM
    {.addr = 0x03, .value = 0x07},  // DIGITAL_CFG: 24-bit format
};

// Master configuration array - loaded by initADC()
PageConfig ADS124S18_sequencer_config[] = {
    {.pageNumber = 0x00, .configPointer = global_page_config, .registerCount = ARRAY_SIZE(global_page_config)},
    {.pageNumber = 0x01, .configPointer = step0_config, .registerCount = ARRAY_SIZE(step0_config)},
    {.pageNumber = 0x02, .configPointer = step1_config, .registerCount = ARRAY_SIZE(step1_config)},
    {.pageNumber = 0x03, .configPointer = step2_config, .registerCount = ARRAY_SIZE(step2_config)},
    {.pageNumber = 0x04, .configPointer = step3_config, .registerCount = ARRAY_SIZE(step3_config)},
};

#define SEQUENCE_SIZE (ARRAY_SIZE(ADS124S18_sequencer_config))
```

These register configurations are **automatically loaded** into the ADC by calling `initADC()`. No manual register writes needed.

## Data Structures (Typedefs)

The driver uses three main data structures for communication:

### STATUS_IO - ADC Status and Error Flags
```C
typedef struct {
    uint8_t STATUS_MSB;      // Summary status (reset, supply, ADC events)
    uint8_t STATUS_LSB;      // SPI and register access error flags
    uint8_t ADC_STATUS;      // ADC-specific status (supply, reference, conversions)
    uint8_t SUPPLY_STATUS;   // Supply voltage monitoring flags
    uint8_t DIGITAL_STATUS;  // Digital interface status
    bool errorPresent;       // Convenience flag if any error detected
} STATUS_IO;
```

**Use:** Returned by `checkStatus()` to detect ADC faults

### ADC_IO - Conversion Result
```C
typedef struct {
    uint32_t    ADC_reading;  // 24-bit (or 16-bit) conversion result
    uint8_t     Register_data;// Raw register value (for reg reads)
    uint8_t    STATUS_MSB;    // STATUS_MSB from conversion (if enabled)
    uint8_t    STATUS_LSB;    // STATUS_LSB from conversion (if enabled)
    bool        CRC_Valid;    // CRC validation result (if SPI_CRC enabled)
} ADC_IO;
```

**Use:** Returned by `readData()` with the latest ADC measurement

### REG_IO - Register Transaction Result
```C
typedef struct {
    uint8_t STATUS_MSB;       // STATUS_MSB from transaction (if enabled)
    uint8_t STATUS_LSB;       // STATUS_LSB from transaction (if enabled)
    uint8_t Register_data;    // Register value read or written
    bool    CRC_Valid;        // CRC validation result (if SPI_CRC enabled)
} REG_IO;
```

**Use:** Returned by `readSingleRegister()` and `writeSingleRegister()`

## Register Definitions and Macros

Register definitions are organized in three header files:

- **ads124s18_pages.h** - Memory page definitions (25 pages: GENERAL_SETTINGS + 24 STEP_X pages)
- **ads124s18_page0.h** - GENERAL_SETTINGS page register definitions
- **ads124s18_page1.h** - STEP_X pages register definitions

Each register definition includes:
- Address constant (e.g., `DEVICE_ID_ADDRESS`)
- Default value (e.g., `DEVICE_ID_DEFAULT`)
- Bit field masks (e.g., `CH_CNT_MASK`, `DEV_ID_MASK`)
- Bit offsets for field extraction

**Example: DEVICE_ID Register (0x00)**
```C
// Register 0x00 - DEVICE_ID
// Bits 7:6  | Bits 5:4  | Bits 3:0
// Reserved  | CH_CNT    | DEV_ID
//
#define DEVICE_ID_ADDRESS                   ((uint8_t) 0x00)
#define DEVICE_ID_DEFAULT                   ((uint8_t) 0x30)

// CH_CNT field (channel count: 0x00=8ch, 0x02=18ch)
#define CH_CNT_MASK                         ((uint8_t) 0x30)
#define DEVICE_ID_CH_CNT_BITOFFSET          (4)
#define DEVICE_ID_CH_CNT_08_MASK            ((uint8_t) 0x00)
#define DEVICE_ID_CH_CNT_18_MASK            ((uint8_t) 0x20)

// DEV_ID field (device variant)
#define DEV_ID_MASK                         ((uint8_t) 0x0F)
#define DEVICE_ID_DEV_ID_BITOFFSET          (0)
#define DEVICE_IS_16_BIT_MASK               ((uint8_t) 0x04)
#define DEVICE_IS_24_BIT_MASK               ((uint8_t) 0x08)
```

All register macros are pre-defined and can be used directly with the driver functions.
```
